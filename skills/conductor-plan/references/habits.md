# 用户习惯适配（habit adaptation）

> 让执行图随用户的习惯“定制”，而不是每次都从默认开始。
> 习惯来自**本次显式偏好 > 当前上下文 > 历史执行图/overview**，优先级从高到低。

## 一、习惯信号从哪来

| 来源 | 提取什么 |
|---|---|
| 本次用户原句 | “快一点/省 token/要详细/最小改动/先别提交/别用子代理”——直接作为本次约束 |
| 当前对话历史 | 用户之前的纠正、否决、确认过的选择 |
| overview（L0 + 需要的 `.details.md`） | 关键决策、用户偏好条目、既往省掉项 |
| 历史执行图（`execution-plan*.json`） | `meta.habit_refs` 里记录的粒度/工具/详略偏好 |
| 目录事实 | 项目语言/结构/已有工具链——决定 ref 可选项 |

## 二、可适配的维度

| 维度 | 取值 | 影响 |
|---|---|---|
| 详略 | 精简 / 标准 / 详细 | 节点数、subplan 层数、action 字段长度 |
| 工具偏好 | 具体脚本/工具优先 vs 通用命令 | `tool` 节点的 ref 选择 |
| 子代理 | 爱用 / 谨慎 / 禁用 | 是否插 `skill:conductor-subagent` 节点 |
| 提交时机 | 每任务提交 / 最后统一 / 先不提交 | `conductor-git` 节点的位置与 skipped 状态 |
| 验证深度 | 全套 / 关键门禁 / 最小 | gate 节点数量与 budget |
| 交互频率 | 少问（自行决策+明示假设）/ 多问（关键节点都确认） | `ask` 节点密度与置信度阈值 |

## 三、适配规则

1. **本次显式 > 历史习惯 > 默认**：用户这次说“别用子代理”，即使历史爱用，本次也不插。
2. **“照上次那样”**：读最近一张同类型执行图的 `meta.habit_refs`，复用其节点粒度/工具/交互频率，只替换 goal 与对象。
3. **习惯必须明示**：把用到的习惯写进图的 `meta.habit_refs`（如 `["用户偏好精简", "先不提交"]`），让用户能在声明里看到并纠正。
4. **冲突时问**：历史习惯与本次上下文冲突（如用户说“快一点”但任务是高风险迁移）→ 插 `ask` 确认，不擅自按习惯省门禁。
5. **习惯不覆盖硬门禁**：无论用户多爱“省事”，conductor 模式的 8 条硬门禁不能因习惯删除——最多写成 skipped + 声明。

## 四、写入图

```json
"meta": {
  "habit_refs": ["用户偏好精简", "先不提交(本次显式)", "谨慎用子代理(历史)"],
  "context_refs": ["overviews/2026-11-21/xxx.md", "execution-plan-prev.json"]
}
```

## 五、边界

- 习惯是**推断**，不是事实；明示供否决，禁止悄悄按习惯改图。
- 无历史、无显式偏好 → 用默认（标准详略、常规工具、门禁齐全、关键节点才问）。
- 本文件只管“图怎么定制”，不管习惯如何持久化到长期记忆（那是 conductor-memory 的职责）。
