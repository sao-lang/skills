# conductor-plan 效果测试方案（端到端）

> 目的：验证规划方法在**真实 LLM 会话**中能否正确推断意图，而不只是校验文档结构与脚本。
> 与 organ_effect_test.py 的区别：那个测脚本接线；本方案测**规划判断质量**（真正导致上次失败的部分）。

## 为什么需要这个测试

2026-11-21 的真实失败：一句并列任务（场景文档 + 改码）被解析成单节点文档路径，声明"不改码"。
当时的三套测试全绿（39/39、26/26、18/18）——因为它们只检查"文档里有没有这句话、脚本能不能跑"，
**没有检查 agent 读到这句话后会不会真的切分任务**。这是测试的盲区。

## 测试设计

### 原则
1. **黑盒**：子代理全新上下文，只给它规划方法 + 用户原句，不给"正确答案"暗示。
2. **自包含**：注入材料完整（prompt + 方法 + 反例库 + schema），不依赖 conductor skill 已加载。
3. **可复现**：固定输入、固定判据、固定评分表。
4. **对照实验**：A 组注入全部修复材料，B 组注入修复**前**的旧方法（若可得）——验证修复确实起作用，而非 agent 本来就会。本轮先做 A 组。

### 测试用例（本次 3 个）

**T1 · 并列任务切分（真实失败案例）**
- 输入：轮1（补充场景落方案；`_l1_rule_intent` 已写完需扩词表）+ 轮2 原话（"前面补充场景的问题，先落方案文档…_l1_rule_intent 去类型化，此表还需要再扩大…往这方向调研一下"）
- 关键判据：切出 **2 个并列任务**；A=文档/场景3；B=**改码**路径（去类型化+扩词表）；调研挂 B（serves_task=B）；两任务可并行派发；无"不改码"声明。

**T2 · 改码信号不被文档词覆盖（消歧）**
- 输入："把现有 `parse_config` 里的类型注解去掉，同时把这块的设计文档更新一下"
- 关键判据：识别出**改码任务**（去类型注解作用于已有代码）+ 文档任务；不得因"设计文档"三字把整体判为文档路径。

**T3 · 调研归属（serves_task）**
- 输入："帮我调研一下 A 库的缓存策略，然后决定要不要改我们的 `cache_layer`"
- 关键判据：调研节点的 `serves_task` 指向 **改 cache_layer 的评估任务**，不能被挂到无关的"只读调研"终点；若信息不足以决定，应有 `ask` 节点。

### 判分表（每例 100 分，≥80 通过）

| 维度 | 分值 | 判据 |
|---|---|---|
| 任务切分 | 30 | 该切几个就几个；T1 必须 2 个且并列 |
| 路径判定 | 25 | 改码/文档路径正确；T1 的 B 必须改码 |
| 调研归属 | 20 | serves_task 指向正确消费者 |
| 控制流与预算 | 15 | 循环/重试带 max_rounds、noop_limit、exit_criteria |
| 声明质量 | 10 | 含假设/置信度/省掉，低置信须 ask 而非硬判 |

### 执行方式
派 1 个全新上下文子代理（general-purpose），注入：
- `plan-prompt.md` 全文（通用规划器提示词）
- `planning-core.md` 全文（判定方法，含 §2.0 修复）
- `cases.md` 全文（反例库）
- `execution-graph-schema.md`（输出契约）
- 3 个测试用例输入

要求它**只输出 3 张 JSON 执行图 + 每题的声明**，不要看我的预期答案。
回收后由我按判分表打分，FAIL 的用例回流修复规划方法。

## 预期输出与验收记录
测试结果写入本文件末尾"测试结果"节，包含：每题得分、关键失误、是否触发修复、修复后复测结果。

**T1 关键验证点**（上次翻车的那句）全部命中：
- 切出 2 个并列任务：t1=场景3文档、t2=场景5/6改码
- 声明明确"t2 `_l1_rule_intent` 去类型化+扩词表 → 场景5/6（改码）"
- 调研 n3 与 think n4 均 `serves_task=t2`，声明写"调研服务于 t2 而非 t1"
- 建议并行派发两个 subplan；无"不改码"错误声明

**T2**：未被"设计文档"三字带偏——去类型注解判改码，文档更新判场景11，末尾加 gate 一致性校验。
**T3**：正确识别"然后"为顺序算子（非并行）；"要不要改"建成 branch + 两条 cond 边而非硬判改码；
主动加 clarifications 确认"若决定改，是否本次执行"——超出判据要求的细致度。

**结论**：修复有效，五层防线在真实规划会话中确实起作用。B 组（修复前方法）对照未做——
如需证明"修复前会失败"，可另派子代理只注入旧版 planning-core（去掉 §2.0 与并列算子）复测 T1。

**待改进**（非阻断）：
