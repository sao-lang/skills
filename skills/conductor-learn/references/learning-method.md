# 学习回写方法

## 抽什么

| overview 来源 | 是否回写 | 写成什么 |
|---|---|---|
| 用户纠正（"不要这么做"） | 必写 | 触发条件 → 禁止动作 → 替代做法 |
| 根因结论（debug） | 必写 | 出现 X 现象 → 先查 Y |
| review Blocker 反复出现 | 必写 | 提交前自检项 |
| 环境阻断及绕法 | 视情况 | 环境信号 → 正确入口命令 |
| 被否决的方案 | 视情况 | 触发条件 → 不要再选 X，原因是 Y |
| 采纳的常规方案 | 不写（除非反直觉） | — |
| 闲聊、未采纳猜测 | 不写 | — |

## 怎么去重

- 同义条目合并到最早那条，保留来源 overview 路径。
- 新条目与旧约定冲突 → 写 `待裁决`，不覆盖。
- 每次回写最多 5 条；超过则按"复用频率 × 后果严重度"排序截断。

## 怎么回写

1. 先 `learn_capture.py --overview <path>` 出草稿。
2. 人工把 `[处理动作] 待补` 改成明确动作。
3. `--apply` 写入目标文件；项目级与技能级分开。
4. 在 overview 收尾段写一行：`learn 回写：N 条 → <目标路径>`。

## 门禁边界

- learn 在 review gate 与 ledger check 之后；不Blocker、不放行。
- 没有 learn 记录不是 finish 的硬阻塞，但 standard/full 必须在 overview 留痕。
- lite 跳过必须在路由声明写进"省掉"。
