# 会话记录（两-tier，省 token）

> **主文件只放 L0（≤8 行）+ 改码时的 review 章节**；环境、L1 摘要、决策、证据、变更清单进 `.details.md`。
> 续接**只读主文件**；需要历史细节才按路径打开详情。禁止把整份历史灌进上下文。

## 文件结构

```
overviews/YYYY-MM-DD/<sid>-<主题>.md            ← 主文件：L0 + review 章节
overviews/YYYY-MM-DD/<sid>-<主题>.details.md    ← 详情：L1/L2（按需打开）
```

`sid` 来自 `.conductor-session.json` 的 8 位短 hash；同会话 append，换任务 `--new-session`。

## 主文件模板（默认只有这一段）

```markdown
# 会话摘要：<主题>

## L0 索引卡（≤8 行）
- 场景 / 路径 / 档位：<...>
- 当前闸门：<未过门禁 + 缺口数 | 全绿>
- 产物：<路径，无则"无">
- 未完成：<≤3 条>
- 下一步：<动作或下一场景>

## 独立 review 报告        ← 仅改码场景；standard/full 内嵌，多轮用 ### Round N
- 结论：Blocker <N> / Should <N> / Nit <N>
- Findings：<文件:行号 + 后果 + 改法>
- Fix loop：<轮次与证据>

## 轻量复核（lite）        ← lite 档替代上节，review_gate --lite 校验
- 档位: lite
- Blocker = 0
- 意图一致：<文件:行号>
- 边界与错误：<文件:行号 或"无新增风险"+依据>
- 证据：verify.py 退出码 0；source_purity 退出码 0

## 详情
- <同名>.details.md（需要历史决策/证据/变更清单时再读）
```

## 详情模板（`.details.md`，按需写、按需读）

```markdown
# 详情：<主题>
## 环境
- 日期 / 项目 / OS / 运行时 / Agent
## L1 摘要（≤6 条）
1. ...
## 关键决策（≤5 条）
- 决策 — 理由（否决也记一行，防重复踩坑）
## 验证证据
- <命令> — 退出码 <N> / 覆盖率 <X%>
## 变更清单（≤15 行）
- <路径:行号> — <摘要>
## 未完成项与下一步（完整）
- <...>
```

## 记什么 / 不记什么

- **记**：诉求与决策、带状态的问题（已解决/待跟进/已否决/环境阻断）、产物路径、验证证据、未完成项。
- **不记**：闲聊、未采纳未落实的调研过程、试错命令、重复状态复述、大段器官输出（用路径引用）。
- 判定："会影响项目后续或下次会话吗？" 否 → 不记；是 → 只记结论与证据。

## 加载协议

1. S0 跑 `scripts/overview_path.py` 定位主文件；`action=append` 追加，`create` 新建。
2. 只读 L0；需要历史决策/验证细节 → 打开 `.details.md`；再需要才进其他 `.xxx.md`。
3. 详情 >30 行才再拆独立文件，主文件只留一行路径。
4. review 报告必须内嵌主文件（门禁要求），不拆成 `.review.md`。

## 纪律

- 脱敏：密钥/token/PII 不写。
- 证据化：命令 + 退出码 / 覆盖率数字，禁止"测试通过"空话。
- 追加不覆盖：同会话多轮叠加时间戳小节，同步更新 L0 的闸门/未完成项/下一步。
- 状态文件：`.conductor-session.json` 只存 `sid`；`.commitment-ledger.json` 紧凑存，详情用 `commitment_ledger.py show` 看；两者均自动加入 `.gitignore`。
