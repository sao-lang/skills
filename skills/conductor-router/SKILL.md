# conductor-router · 路由器官

> **器官类型**：路由（神经中枢） —— 输入用户原句 → 输出执行图 + 档位声明；只规划，不执行不放行
> conductor 机体的"神经中枢"：只做规划，不写代码、不跑门禁。

## 输入
用户原句 + 可选事实：目录是否为空、是否有设计文档、是否有报错栈、代码是否已存在。

## 输出（严格结构）
```
拓扑: 单节点/链/分支/并行
节点: [{场景, 路径, 档位, 输入契约, 输出契约}]
边: [{from, to, 类型, 闸门}]   ← 单节点/并行写 []
置信度: 0.00~1.00
假设: [...]  待澄清: [...]  省掉: [...]
```
声明必须含「场景 / 路径 / 档位 / 省掉」；未声明不推进。

## 执行
1. 结构算子定拓扑（顺序/条件/否定/并行/回指）。
2. 语义三问定场景+路径：产出物、对象、时序。
3. 用 `references/scenarios.md` 的 I/O 契约表校验边。
4. 判档：high 条件→full；lite 条件全中→lite；其余 standard（见 `cost-tiers.md`）。
5. 置信度闸门：≥0.8 执行，0.5–0.8 确认，<0.5 问用户；假设必须明示。

## 方法源（共享组织，不是第二个大脑）
- `references/routing.md`（五层管线、消歧、声明模板）
- `references/cost-tiers.md`（三档判定与裁剪）
- `references/router-prompt.md`（可独立注入的自包含提示词）

## 降级
匹配不上或低置信且用户未回应 → 降级只读场景 9/10，输出问题清单；**绝不猜改码场景硬跑**。用户一句话纠正 → 立即重路由。

## 本器官自带（可独立工作）
- `SKILL.md`：角色、I/O、执行与降级
- `references/`：从 conductor 拆分的路由方法文档（scenarios / cost-tiers / routing / router-prompt）
- `scripts/`：无（路由是纯规划，不需要确定性脚本）
