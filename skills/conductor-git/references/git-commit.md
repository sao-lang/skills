# commit：提交纪律

> 由 conductor-git 在每个任务的 GREEN 后调用；RED 阶段不提交。

## 何时提交

- 每个任务 RED→GREEN 完成、测试全绿后提交一次；REFACTOR 保持绿，重构完成可再提交一次。
- 一个提交 = 一个完整任务（测试+实现一起），不提交半成品；失败测试与实现分离提交只允许在明确要求"保存进度"时。

## 怎么提交

1. **精确暂存**：`git add` 只加本任务的精确文件路径（来自计划/任务说明），**不用 `git add -A`/`git add .` 盲加**；
   提交前跑 `git status --short` 核对暂存清单，发现不属于本任务的文件 → 停下问用户。
2. **message 规范**：首行 ≤72 字符说清"做了什么"；正文说"为什么"（决策、取舍、关联的规格条目）；
   不写"update / fix / misc"这类零信息 message。
3. **hooks**：pre-commit/commit-msg 失败 = 修根因后重提交；**禁止 `--no-verify` 跳过**，除非用户明确要求并说明后果。
4. **留证据**：commit hash 记入 overview 变更清单；消息里引用的 issue/规格编号要真实存在。

## 红线

| 借口 | 真相 |
|---|---|
| "先全部暂存省事" | 无关文件混进提交，回滚粒度被破坏；精确暂存 |
| "hook 挡路，跳过就好" | hook 挡住的是真问题；修根因，不跳过 |
| "测试晚点跑，先提交" | 绿灯才提交；红灯提交污染基线，后续 bisect 全废 |
| "message 回头补" | 没有"回头"，push 后的 message 不可靠改写 |
| "顺便把别人的改动提交了" | 暂存清单核对；不属于本任务的文件停下问用户 |
| "push 被拒，强推修复" | 被拒说明远端变了，先调查；强推需用户明确要求 |
