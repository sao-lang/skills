# 系统化调试（conductor 内置工程纪律）

> 来源致谢：提取自 obra/superpowers 上游的 `systematic-debugging/SKILL.md`，本地化重述。

不靠猜。用 4 阶段根因流程定位问题，再修。

## 4 阶段

1. **复现**：写出能稳定触发 bug 的最小步骤 / 测试。复现不了就不算定位。
2. **根因追踪 root-cause-tracing**：沿调用链往下，用日志 / 断点确认"真相在哪一层"，而不是在现象层打补丁。
3. **纵深防御 defense-in-depth**：修根因的同时，在相邻边界加一道保护（例如输入校验），防止同类问题换皮重现。
4. **条件等待 condition-based-waiting**：对竞态 / 时序类问题，用"等到条件成立"而非"睡 N 秒"。

## 最小复现构造（场景 8 切入点）

AI 解 bug 最常见的失败是**不先造复现就猜原因**。从 issue/报错到最小用例：

1. **锁定症状**：把"用户说的问题"改写成可观察断言——期望行为 vs 实际行为，含输入与触发条件。
2. **缩到最小**：逐步删减无关步骤/数据/依赖，直到再删一步就不复现。最小用例是后续 TDD 的 RED 测试种子。
3. **固定下来**：写成自动化测试（不只是手工步骤），确保**当前必红**——红了才证明复现成功；若绿了，说明没抓住 bug，回到第 1 步。
4. **有上下文再追根因**：拿到"稳定复现的最小红测试"后，才进入 4 阶段根因法的第 2 步（root-cause-tracing）。复现不了就别声称定位。

> 判定：没有可运行的最小复现 = 没到追根因的资格。禁止跳过此步直接改代码。

## 完成前验证

- 修复后，先跑**能复现原 bug 的测试**，确认它现在绿。
- 再跑**相关回归测试**，确认没引入新问题。
- 只在"真的修好了"时才宣布完成——证据是测试，不是感觉。

## 纪律

- 没调查，不修复。
- 一次只改一个变量来定位，别同时改三处。
