# 会话记录规范（overviews）

> 每轮会话一个 md 文件，按日期分目录，存于**项目根** `overviews/YYYY-MM-DD/`。
> 用于跨会话交接、审计与进度追踪。写入前必须脱敏。
>
> **分层原则（省 token）**：overview 分为「L0 索引卡」与「L1/L2 详情」。
> 续接时**先只读 L0**（~10 行）即可定位状态，需要细节再按路径加载详情文件。
> 严禁一上来全量加载整份 overview——那会把当时的过程记录变成噪声吃掉上下文。

## 路径规则

```
overviews/
└── YYYY-MM-DD/
    ├── YYYYMMDD-HHMM-主题.md           ← 主文件：L0 索引卡 + L1 摘要
    ├── YYYYMMDD-HHMM-主题.review.md    ← 详情：完整 review 报告（按需建）
    ├── YYYYMMDD-HHMM-主题.questions.md ← 详情：完整问题清单（按需建）
    └── ...
```

- 日期目录按会话发生日期（本地时间）。
- 文件名含时间戳与短主题，避免同日多会话重名。
- 同一轮会话内的多次更新**追加到同一主文件**的时间戳小节，不新建主文件。
- **详情过大（>30 行）时独立成同名 `.xxx.md` 文件**，主文件只留一行路径引用。

## 文件模板

```markdown
# 会话摘要：<主题>

## L0 索引卡（续接时先读这一段，≤12 行）
- 场景 / 路径：<场景 N 名称> / <改码|只读|文档|验证>
- 当前闸门：<未过门禁名 + 缺口数 | 全绿>
- 交付产物：<路径1>, <路径2>（图/报告/spec 等，无则写"无"）
- 未完成项：<最多 3 条，超出写"详见 L1">
- 下一步：<下一场景或动作>

## 环境
- 日期时间：YYYY-MM-DD HH:MM TZ
- 项目：<项目名> / 工作区：<绝对路径>
- OS / Shell：<...>
- 运行时：<Python/Node/Go/Rust/Dart 版本>
- IDE / Agent：<...>

## 场景与 skill
- 场景：<初始化/开发/迭代/重构/解bug/拷问>
- 加载的 skill：<列表>
- 主控：conductor（唯一流程主控）

## L1 摘要（需要背景时读）
### 会话摘要（≤10 条要点）
1. ...
2. ...
### 关键决策与理由
- 决策：<...> — 理由：<...>
### 验证结果
- 测试：<命令> — 通过 X/Y
- 覆盖率：<X%>（阈值 <Y%>）
- Linter / Formatter / Type：<命令> — 退出码 0 / 非 0
- 缺口台账：功能遗漏 □ / 功能断点 □ / 覆盖盲区 □（各附证据）
- Code review：<Critical/Major/Minor 数>
### 未完成项与下一步（完整）
- <...>
- suggested skills：<下一会话建议加载的 skill>

## L2 详情引用（用到才按路径加载，禁止复制正文）
- 设计审查问题清单：<主题>.questions.md
- 独立 review 报告：<主题>.review.md
- 变更文件清单：<path>:<line> — <改动摘要>（≤15 行，超出独立成 .changes.md）

## 交接
- handoff 文档路径：<...>（若生成）
- 脱敏声明：本文件不含密钥 / token / PII
```

## 加载协议（S0 续接时遵守）

1. **先读 L0**：从最近一份 overview 的「L0 索引卡」读取场景、闸门、产物路径、下一步。
2. **按需读 L1**：仅当需要历史决策 / 验证细节时读「L1 摘要」。
3. **按路径读 L2**：L2 只有路径引用，需要时打开对应 `.xxx.md`；不存在则跳过。
4. **禁止全量**：不得在 S0 把整份 overview（尤其带时间戳的多次续写）一次性塞进上下文。

## 纪律

1. **脱敏**：API key、密码、token、PII 一律不写入；写交接文档时尤其注意。
2. **证据化**：验证结果必须带命令与退出码 / 覆盖率数字，禁止"测试通过"这类无证据表述。
3. **引用不复制**（硬要求）：已有产物（spec / plan / diff / commit / review 报告 / 问题清单）用路径引用，**不在 overview 里重复全文**；超过 30 行的详情必须独立成文件。
4. **追加不覆盖**：一轮会话内多次更新追加到同一主文件的时间戳小节；追加时同步更新 L0 索引卡的"当前闸门 / 未完成项 / 下一步"。
5. **未完成项必列**：未关闭的 failure / 技术债显式登记，禁止静默略过（对应 R5-GAP-LIST 的"拿不出行号不得标完成"纪律）。
6. **L0 必填**：每份 overview 必须有 L0 索引卡且 ≤12 行——这是续接时唯一保证读取的部分，字段缺失视为该轮 overview 未完成。
