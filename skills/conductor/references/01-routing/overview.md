# 会话记录规范（overviews）

> **一个会话（session）一个 md 主文件**——不是"一轮对话一个"。按日期分目录，存于**项目根** `overviews/YYYY-MM-DD/`。
> 用于跨会话交接、审计与进度追踪。写入前必须脱敏。
>
> **分层原则（省 token）**：overview 分为「L0 索引卡」与「L1/L2 详情」。
> 续接时**先只读 L0**（~10 行）即可定位状态，需要细节再按路径加载详情文件。
> 严禁一上来全量加载整份 overview——那会把当时的过程记录变成噪声吃掉上下文。

## 新建 vs 追加（关键，别搞错）

**默认追加，不要动不动新建文件。** 会话 = 一段连续的工作（围绕同一目标/同一任务链，可能跨越多轮对话）。
按下面的判定决定动作：

| 情形 | 动作 |
|---|---|
| 当前项目 `overviews/YYYY-MM-DD/` 下**已有**当天的主文件，且本轮是对它的延续（同一任务链、同一天的后续对话、补充/迭代/复盘已记录的工作） | **追加**：在同一主文件里新增一个带时间戳的小节，并同步更新 L0 索引卡的「当前闸门/未完成项/下一步」 |
| 确认是**全新的会话**——换了不相关的任务目标、跨天、或用户显式说"新开一个会话/新任务" | **新建**：按下方命名规则创建新的主文件 |

**如何判断"是不是同一会话"（避免每轮都新建）：**
1. 先看当天目录里有没有主文件——有，就**默认追加**，除非明确是无关的新任务。
2. 看工作内容是否与最近一份主文件的 L0「下一步」衔接——衔接得上 = 同一会话，追加；完全无关 = 新会话，新建。
3. 拿不准时**追加而非新建**（宁可一个文件里多几个时间戳小节，也不要散落一堆文件）。
4. 一轮对话里对本会话工作做了多次记录 → 都在**同一主文件**内追加小节，不新建。

> 一句话：**同一天、同一目标链的工作 = 一个文件；只有真正换任务/换天/用户要求才新建。**

## 记什么 / 不记什么（过滤规则，省篇幅且防噪声）

overview 的目的是**跨会话续接 + 审计**，不是对话逐字稿。只记录对项目**有实际影响**或**后续要跟进**的内容；
大量"聊了但没落地"的东西会稀释真正的问题，必须过滤。

### 一律不记（写了就是噪声）

| 类型 | 例子 | 处理 |
|---|---|---|
| 与项目无关的对话 | 闲聊、生活琐事、别的项目的事、与本轮任务无关的边角问题 | 完全略过，不进 overview |
| 未采纳、未落实的调研/方案 | 讨论了 A/B/C 方案最终没选；调研了某技术但没用；设计了一版方案被否决或搁置且没有落地动作 | 略过过程。**例外**：若该决策影响后续（如"否决 X 因 Y 原因"能防重复踩坑），只在「关键决策」记一行结论，不展开调研细节 |
| 中间试错与过程噪声 | 试错命令、走不通的分支、临时文件、反复调整的格式 | 略过，只留最终结论与证据 |
| 重复的状态复述 | 同一事实在 L0/L1/多轮小节里反复写 | 只在一处记，其余用引用 |

### 必须记（对项目有实际影响或要跟进）

- **用户诉求与决策**：本轮要解决什么问题、拍板了什么（尤其否定/取舍——防反复）。
- **发现的问题**：带严重度/行号/证据的问题清单，以及每个问题的**状态**（已解决 / 待跟进 / 已否决）。
- **实际改动与产物**：代码/文档改了什么（路径+行号）、commit、产物路径。
- **验证证据**：命令 + 退出码 / 覆盖率数字。
- **未关闭项与下一步**：技术债、待拍板、待验证——续接的关键。

> 判定口径：**"这件事会不会影响项目后续、或下次会话需要知道？"** 否 → 不记；是 → 记结论与证据，不记过程。

## 路径规则

```
overviews/
└── YYYY-MM-DD/
    ├── YYYYMMDD-HHMM-主题.md           ← 主文件：L0 索引卡 + L1 摘要
    ├── YYYYMMDD-HHMM-主题.review.md    ← 详情：完整 review 报告（按需建）
    ├── YYYYMMDD-HHMM-主题.questions.md ← 详情：完整问题清单（按需建）
    └── ...
```

- 日期目录按会话发生日期（本地时间）。
- 文件名含时间戳与短主题，避免同日多个**独立会话**重名（同一会话内追加不换文件名）。
- **同一会话内的多轮对话、多次更新，追加到同一主文件**的带时间戳小节，不新建主文件（判定见上节）。
- **详情过大（>30 行）时独立成同名 `.xxx.md` 文件**，主文件只留一行路径引用。

## 文件模板

```markdown
# 会话摘要：<主题>

## L0 索引卡（续接时先读这一段，≤12 行）
- 场景 / 路径：<场景 N 名称> / <改码|只读|文档|验证>
- 当前闸门：<未过门禁名 + 缺口数 | 全绿>
- 交付产物：<路径1>, <路径2>（图/报告/spec 等，无则写"无"）
- 未完成项：<最多 3 条，超出写"详见 L1">
- 下一步：<下一场景或动作>

## 环境
- 日期时间：YYYY-MM-DD HH:MM TZ
- 项目：<项目名> / 工作区：<绝对路径>
- OS / Shell：<...>
- 运行时：<Python/Node/Go/Rust/Dart 版本>
- IDE / Agent：<...>

## 场景与 skill
- 场景：<初始化/开发/迭代/重构/解bug/拷问>
- 加载的 skill：<列表>
- 主控：conductor（唯一流程主控）

## L1 摘要（需要背景时读）
### 会话摘要（≤10 条要点）
1. ...
2. ...
### 关键决策与理由
- 决策：<...> — 理由：<...>
### 验证结果
- 测试：<命令> — 通过 X/Y
- 覆盖率：<X%>（阈值 <Y%>）
- Linter / Formatter / Type：<命令> — 退出码 0 / 非 0
- 缺口台账：功能遗漏 □ / 功能断点 □ / 覆盖盲区 □（各附证据）
- 技术债：债指数 <N>（debt_ledger.py）/ 未关闭项数 <N>（详见 `.debts.md` 或 L1）
- Code review：<Critical/Major/Minor 数>
### 未完成项与下一步（完整）
- <...>
- suggested skills：<下一会话建议加载的 skill>

## L2 详情引用（用到才按路径加载，禁止复制正文）
- 设计审查问题清单：<主题>.questions.md
- 独立 review 报告：<主题>.review.md
- 变更文件清单：<path>:<line> — <改动摘要>（≤15 行，超出独立成 .changes.md）

## 交接
- handoff 文档路径：<...>（若生成）
- 脱敏声明：本文件不含密钥 / token / PII

## 追加记录（同一会话的后续轮次，在此叠加，不新建文件）
### HHMM 续：<一句话主题>
- 用户诉求：<本轮要做什么，一句话；与项目无关的不写>
- 场景 / 动作：<场景 N / 做了什么>
- 本轮问题与状态（逐条，只记有影响的）：
  - [已解决] <问题> — <结论/证据（路径:行号 或 命令+退出码）>
  - [待跟进] <问题> — <卡在哪 / 下一步>（转入 L0「未完成项」）
  - [已否决] <方案/建议> — <否决理由>（防重复，可选）
- 产物 / 改动：<路径:行号 或 commit；无则"无">
- 闸门 / 下一步：<...>（同步更新 L0）

> 每个 `### HHMM` 小节 = 一轮对话；**没解决问题、没产物、没决策的纯闲聊轮次整段略过，不建小节**。
```

## 加载协议（S0 续接时遵守）

1. **先读 L0**：从最近一份 overview 的「L0 索引卡」读取场景、闸门、产物路径、下一步。
2. **按需读 L1**：仅当需要历史决策 / 验证细节时读「L1 摘要」。
3. **按路径读 L2**：L2 只有路径引用，需要时打开对应 `.xxx.md`；不存在则跳过。
4. **禁止全量**：不得在 S0 把整份 overview（尤其带时间戳的多次续写）一次性塞进上下文。

## 纪律

1. **脱敏**：API key、密码、token、PII 一律不写入；写交接文档时尤其注意。
2. **证据化**：验证结果必须带命令与退出码 / 覆盖率数字，禁止"测试通过"这类无证据表述。
3. **引用不复制**（硬要求）：已有产物（spec / plan / diff / commit / review 报告 / 问题清单）用路径引用，**不在 overview 里重复全文**；超过 30 行的详情必须独立成文件。
4. **追加不覆盖**：同一会话内多次更新追加到同一主文件的时间戳小节，禁止每轮对话新建文件；追加时同步更新 L0 索引卡的"当前闸门 / 未完成项 / 下一步"。
5. **未完成项必列**：未关闭的 failure / 技术债显式登记，禁止静默略过（对应 R5-GAP-LIST 的"拿不出行号不得标完成"纪律）。
6. **L0 必填**：每份 overview 必须有 L0 索引卡且 ≤12 行——这是续接时唯一保证读取的部分，字段缺失视为该轮 overview 未完成。
7. **只记有影响的**：按「记什么 / 不记什么」过滤——与项目无关的对话、未采纳未落实的调研/方案、中间试错一律不写；每个问题带状态（已解决/待跟进/已否决）。宁可少记，不堆噪声。
