# 会话记录规范（overviews）

> **一个会话（session）一个 md 主文件**——不是"一轮对话一个"。按日期分目录，存于**项目根** `overviews/YYYY-MM-DD/`。
> 用于跨会话交接、审计与进度追踪。写入前必须脱敏。
>
> **分层原则（省 token）**：overview 分为「L0 索引卡」与「L1/L2 详情」。
> 续接时**先只读 L0**（~10 行）即可定位状态，需要细节再按路径加载详情文件。
> 严禁一上来全量加载整份 overview——那会把当时的过程记录变成噪声吃掉上下文。

## 新建 vs 追加（关键——用会话指针锚定，跨 agent 通用）

**S0 必须先跑脚本定位文件，不要靠语义猜"是不是同一会话"：**

```bash
python scripts/overview_path.py --project-root . --topic "<本会话短主题>"
# → JSON: {session_id, shorthash, path, action: create|append, existed, pointer}
```

脚本维护一个**会话指针文件** `.conductor-session.json`（项目根），存当前会话的 UUID：
- 指针的 8 位短 hash 做文件名前缀（`overviews/YYYY-MM-DD/<shorthash>-<主题>.md`）——同会话前缀相同。
- S0 读指针 → 按 hash 递归找已有 overview → 找到即 `append`（**与主题无关**，主题变了也归到同一文件）。
- 用户明确换任务/新会话时，带 `--new-session` → 生成新 UUID → 下一个新文件。
- 会话结束用 `--end-session`；`--detect-only` 只看状态不改文件。

**为什么用指针文件而不是环境变量**：`CODEBUDDY_SESSION_ID`/`CLAUDE_SESSION_ID` 等各家不统一，没有跨 agent 通用的 key；
而"读写项目文件"是所有 agent 都具备的能力。指针文件零外部依赖、支持跨天同一会话、边界由用户显式控制。

| 脚本返回 | 动作 |
|---|---|
| `action: append` | **追加**：打开 `path`，新增一个 `### HHMM 续：<主题>` 小节，同步更新 L0 索引卡的「当前闸门/未完成项/下一步」 |
| `action: create` | **新建**：按 `path` 建主文件，写 L0 索引卡 + 环境 + L1 摘要 |

> 一句话：**S0 跑脚本，append 就追加、create 就新建；换任务时 `--new-session`。绝不靠猜，也绝不每轮新建。**
> 指针文件 `.conductor-session.json` 建议加入 `.gitignore`（它是本地会话状态，非项目资产）。

## 记什么 / 不记什么（过滤规则，省篇幅且防噪声）

overview 的目的是**跨会话续接 + 审计**，不是对话逐字稿。只记录对项目**有实际影响**或**后续要跟进**的内容；
大量"聊了但没落地"的东西会稀释真正的问题，必须过滤。

### 一律不记（写了就是噪声）

| 类型 | 例子 | 处理 |
|---|---|---|
| 与项目无关的对话 | 闲聊、生活琐事、别的项目的事、与本轮任务无关的边角问题 | 完全略过，不进 overview |
| 未采纳、未落实的调研/方案 | 讨论了 A/B/C 方案最终没选；调研了某技术但没用；设计了一版方案被否决或搁置且没有落地动作 | 略过过程。**例外**：若该决策影响后续（如"否决 X 因 Y 原因"能防重复踩坑），只在「关键决策」记一行结论，不展开调研细节 |
| 中间试错与过程噪声 | 试错命令、走不通的分支、临时文件、反复调整的格式 | 略过，只留最终结论与证据 |
| 重复的状态复述 | 同一事实在 L0/L1/多轮小节里反复写 | 只在一处记，其余用引用 |

### 必须记（对项目有实际影响或要跟进）

- **用户诉求与决策**：本轮要解决什么问题、拍板了什么（尤其否定/取舍——防反复）。
- **发现的问题**：带严重度/行号/证据的问题清单，以及每个问题的**状态**（已解决 / 待跟进 / 已否决 / 环境阻断）。
  - 「环境阻断」专指测试报错根因是真实环境不可用（Docker/DB 连不上、缺驱动），**已告知用户且 AI 无法解决**，可暂忽略该项；须写明报错与所需环境，禁止用它掩盖代码 bug。
- **实际改动与产物**：代码/文档改了什么（路径+行号）、commit、产物路径。
- **验证证据**：命令 + 退出码 / 覆盖率数字。
- **未关闭项与下一步**：技术债、待拍板、待验证——续接的关键。

> 判定口径：**"这件事会不会影响项目后续、或下次会话需要知道？"** 否 → 不记；是 → 记结论与证据，不记过程。

## 路径规则

```
overviews/
└── YYYY-MM-DD/
    ├── <shorthash>-<主题>.md           ← 唯一主文件：L0 + L1 + 内嵌 review 报告
    └── <主题>.questions.md             ← 仅问题清单等大块详情才独立（按需）
```

- 文件名前缀 `shorthash` 由 `overview_path.py` 从会话指针生成（见「新建 vs 追加」），同会话稳定。
- **同一会话的多轮对话、多次 review，全部写进同一个主文件**，不新建主文件、不拆 review 文件。
- **独立 review 报告内嵌为主文件附录章节** `## 独立 review 报告`（多轮用 `### Round N` 分节），
  不生成 `.review.md/.review2.md`——门禁 `review_gate.py` 已支持内嵌章节作为证据。
- 仅当问题清单等**非 review 详情**过大（>30 行）时独立成 `.questions.md`，主文件留一行路径引用。

## 文件模板

```markdown
# 会话摘要：<主题>

## L0 索引卡（续接时先读这一段，≤12 行）
- 场景 / 路径：<场景 N 名称> / <改码|只读|文档|验证>
- 当前闸门：<未过门禁名 + 缺口数 | 全绿>
- 交付产物：<路径1>, <路径2>（图/报告/spec 等，无则写"无"）
- 未完成项：<最多 3 条，超出写"详见 L1">
- 下一步：<下一场景或动作>

## 环境
- 日期时间：YYYY-MM-DD HH:MM TZ
- 项目：<项目名> / 工作区：<绝对路径>
- OS / Shell：<...>
- 运行时：<Python/Node/Go/Rust/Dart 版本>
- IDE / Agent：<...>

## 场景与 skill
- 场景：<初始化/开发/迭代/重构/解bug/拷问>
- 加载的 skill：<列表>
- 主控：conductor（唯一流程主控）

## L1 摘要（需要背景时读）
### 会话摘要（≤10 条要点）
1. ...
2. ...
### 关键决策与理由
- 决策：<...> — 理由：<...>
### 验证结果
- 测试：<命令> — 通过 X/Y
- 覆盖率：<X%>（阈值 <Y%>）
- Linter / Formatter / Type：<命令> — 退出码 0 / 非 0
- 缺口台账：功能遗漏 □ / 功能断点 □ / 覆盖盲区 □（各附证据）
- 技术债：债指数 <N>（debt_ledger.py）/ 未关闭项数 <N>（详见 `.debts.md` 或 L1）
- Code review：<Critical/Major/Minor 数>
### 未完成项与下一步（完整）
- <...>
- suggested skills：<下一会话建议加载的 skill>

## 独立 review 报告（改码场景必填，内嵌不拆文件）
- 见下方独立的 `## 独立 review 报告` 章节（多轮用 `### Round N` 分节，含分级+行号证据）
- 结论同步在 L1「独立 review 结果」节写 Blocker 清零状态

## L2 详情引用（仅非 review 的大块详情，按需加载）
- 设计审查问题清单：<主题>.questions.md（>30 行才独立）
- 变更文件清单：<path>:<line> — <改动摘要>（≤15 行，超出独立成 .changes.md）

## 交接
- handoff 文档路径：<...>（若生成）
- 脱敏声明：本文件不含密钥 / token / PII

## 追加记录（同一会话的后续轮次，在此叠加，不新建文件）
### HHMM 续：<一句话主题>
- 用户诉求：<本轮要做什么，一句话；与项目无关的不写>
- 场景 / 动作：<场景 N / 做了什么>
- 本轮问题与状态（逐条，只记有影响的）：
  - [已解决] <问题> — <结论/证据（路径:行号 或 命令+退出码）>
  - [待跟进] <问题> — <卡在哪 / 下一步>（转入 L0「未完成项」）
  - [已否决] <方案/建议> — <否决理由>（防重复，可选）
  - [环境阻断] <测试报错> — 需 <Docker/DB/...>，已告知用户，AI 无法解决，暂忽略（非代码 bug）
- 产物 / 改动：<路径:行号 或 commit；无则"无">
- 闸门 / 下一步：<...>（同步更新 L0）

> 每个 `### HHMM` 小节 = 一轮对话；**没解决问题、没产物、没决策的纯闲聊轮次整段略过，不建小节**。

## 独立 review 报告（改码场景；多轮在此叠加，不新建 .review.md）
### Round 1：<审查类型，如"七维+接线四问">
- 审查人 / 方式：<全新上下文子代理 / 基线 commit / 方法>
- 结论：Blocker <N> / Should <N> / Nit <N>；<是否可合入>
- Findings（逐条带 文件:行号 + 后果 + 改法）：
  - [Blocker] <问题> — <文件:行号> — <改法>
  - [Should] <问题> — <文件:行号> — <建议>
- Fix loop 轮次 / 复审结论：<...>；Blocker 清零证据：<命令+退出码>
> 复审再来一轮就加 `### Round 2`；门禁 `review_gate.py` 检查本报告章节存在且有分级/证据。
```

## 加载协议（S0 续接时遵守）

1. **先读 L0**：从最近一份 overview 的「L0 索引卡」读取场景、闸门、产物路径、下一步。
2. **按需读 L1**：仅当需要历史决策 / 验证细节时读「L1 摘要」。
3. **按路径读 L2**：L2 只有路径引用，需要时打开对应 `.xxx.md`；不存在则跳过。
4. **禁止全量**：不得在 S0 把整份 overview（尤其带时间戳的多次续写）一次性塞进上下文。

## 纪律

1. **脱敏**：API key、密码、token、PII 一律不写入；写交接文档时尤其注意。
2. **证据化**：验证结果必须带命令与退出码 / 覆盖率数字，禁止"测试通过"这类无证据表述。
3. **引用不复制，但 review 报告例外**（硬要求）：spec / plan / diff / commit 等已有产物用路径引用，不重复全文；**独立 review 报告必须内嵌在主文件**（`## 独立 review 报告` 章节，多轮用 `### Round N`），不生成 `.review.md/.review2.md` 散落文件——门禁靠该章节判定；仅问题清单等非 review 大块详情（>30 行）独立成 `.questions.md`。
4. **追加不覆盖**：同一会话内多次更新追加到同一主文件的时间戳小节，禁止每轮对话新建文件；追加时同步更新 L0 索引卡的"当前闸门 / 未完成项 / 下一步"。
5. **未完成项必列**：未关闭的 failure / 技术债显式登记，禁止静默略过（对应 R5-GAP-LIST 的"拿不出行号不得标完成"纪律）。
6. **L0 必填**：每份 overview 必须有 L0 索引卡且 ≤12 行——这是续接时唯一保证读取的部分，字段缺失视为该轮 overview 未完成。
7. **只记有影响的**：按「记什么 / 不记什么」过滤——与项目无关的对话、未采纳未落实的调研/方案、中间试错一律不写；每个问题带状态（已解决/待跟进/已否决）。宁可少记，不堆噪声。
