# dispatch：子代理派发纪律

> 由 conductor-subagent 在派发每个任务时使用。核心目标：**主上下文当调度台，子代理自包含干活**。

## 任务 brief 模板（每任务一份，自包含）

```
# 任务 N：<组件名>
## 目标
<一句话：这个任务产出什么>
## 文件
- Create: <精确路径>
- Modify: <精确路径:行号>
- Test: <精确路径>
## 接口（Interfaces）
- Consumes: <本任务用到的、前面任务产出的精确签名>
- Produces: <后续任务依赖的精确函数名/参数/返回类型>
## 步骤
1. 写失败测试（代码+断言，规格精确值）
2. 跑测试确认失败（命令+预期失败信息）
3. 实现（签名/测试已决定的部分不写函数体）
4. 跑测试确认通过（命令+预期输出）
## 完成标准
<验证命令 + 预期退出码>
```

- brief 里没有的信息**等于不存在**——子代理看不到主对话，不要指望它"猜"。
- 精确值（路径/签名/断言值）只出现在 brief，不靠口头传递；这是子代理知道邻近任务用什么名字的唯一途径。
- Interfaces 块不可省：这是任务间衔接的唯一契约。

## 注入最小集

只给子代理三样：**本任务 brief + 计划头（Goal/Architecture/Spec 路径）+ 完成标准里的验证命令**。
不给：整个计划全文、主对话历史、其他任务的完整实现（只给它们的 Interfaces 签名）。
不给的理由：多注入一份就多一份污染源，且 token 与上下文占用翻倍。

## 防污染纪律

1. **每任务全新子代理**：不复用上一个任务的子代理（它已被上一个任务污染）。
2. **返修重派**：评审发现 Blocker → 修 brief（补缺失信息）→ **重派全新子代理**，禁止把旧报告喂给旧子代理继续改。
3. **结果只回收结论**：主上下文记录「任务 N：通过 / 返修原因（文件:行号）」一行；子代理的完整输出不回灌。
4. **失败升级**：同一任务连续返修 ≥2 轮 → 停止派发，报告用户（多半是 brief 缺关键信息或任务该拆）。

## 评审（两段，规则全文在 conductor-review）

1. 规格符合度：产出是否恰好实现 brief 承诺的范围，无夹带。
2. 代码质量：七维审查（正确性/错误处理/并发/资源/性能/安全/可维护性）。
Critical/Blocker 清零才进下一任务。

## 与成本的关系

- 派发省的是**主上下文占用**（长会话质量），花的是**token**（每个子代理重复注入框架知识）。
- 收益判据见 SKILL.md 派发判据；核心是"任务独立数量"与"会话长度"——两者都不达标就不派。
- 用户明确要求省 token / 快速出结果 → 不派，写进声明。
