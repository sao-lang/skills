# dispatch：子代理派发纪律

> 由 conductor-subagent 在派发每个任务时使用。核心目标：**主上下文当调度台，子代理自包含干活**。
> 适用于任何可拆分的任务类型：改码、调研、分析、文档、审查——差别只在 brief 模板。

## 任务 brief 模板（每任务一份，自包含）

### A. 改码任务

```
# 任务 N：<组件名>
## 目标
<一句话：这个任务产出什么>
## 文件
- Create: <精确路径>
- Modify: <精确路径:行号>
- Test: <精确路径>
## 接口（Interfaces）
- Consumes: <本任务用到的、前面任务产出的精确签名>
- Produces: <后续任务依赖的精确函数名/参数/返回类型>
## 步骤
1. 写失败测试（代码+断言，规格精确值）
2. 跑测试确认失败（命令+预期失败信息）
3. 实现（签名/测试已决定的部分不写函数体）
4. 跑测试确认通过（命令+预期输出）
## 完成标准
<验证命令 + 预期退出码>
```

- 精确值（路径/签名/断言值）只出现在 brief，不靠口头传递；Interfaces 块不可省——这是任务间衔接的唯一契约。

### B. 非改码任务（调研/分析/文档/审查）

```
# 任务 N：<主题>
## 目标
<一句话：这个任务回答什么问题 / 产出什么>
## 输入材料
- <源文件路径 / URL / 前置任务结论的精确引用>
## 产出要求
- <结构/格式/篇幅要求；逐条列出必须覆盖的点>
## 完成标准
<怎么验证：覆盖了全部点 / 结论有证据源（文件:行号或链接）/ 无臆测>
```

## brief 通用纪律

- brief 里没有的信息**等于不存在**——子代理看不到主对话，不要指望它"猜"。
- 产出定义、输入材料、完成标准三项缺一不可；验证方式写不出来的任务先不派（说明它还没拆清楚）。

## 注入最小集

只给子代理三样：**本任务 brief + 全局上下文的最小头（目标/架构/规格路径一句话）+ 完成标准里的验证方式**。
不给：任务集全文、主对话历史、其他任务的完整产出（只给它们的显式契约：Interfaces 签名或结论引用）。
不给的理由：多注入一份就多一份污染源，且 token 与上下文占用翻倍。

## 防污染纪律

1. **每任务全新子代理**：不复用上一个任务的子代理（它已被上一个任务污染）。
2. **返修重派**：评审/复核发现问题 → 修 brief（补缺失信息）→ **重派全新子代理**，禁止把旧报告喂给旧子代理继续改。
3. **结果只回收结论**：主上下文记录「任务 N：通过 / 返修原因（文件:行号或证据源）」一行；子代理的完整输出不回灌。
4. **失败升级**：同一任务连续返修 ≥2 轮 → 停止派发，报告用户（多半是 brief 缺关键信息或任务该拆）。

## 复核（按任务类型，规则全文由 conductor 编排对应器官提供）

- **改码任务，两段**：① 规格符合度——产出是否恰好实现 brief 承诺的范围，无夹带；② 代码质量——七维审查。
  Critical/Blocker 清零才进下一任务。
- **非改码任务，两查**：① 结论正确性——抽查证据源（文件:行号/链接），臆测即打回；② 覆盖完整性——对照 brief 产出要求逐条勾销，缺漏即补 brief 重派。

## 与成本的关系

- 派发省的是**主上下文占用**（长会话质量），花的是**token**（每个子代理重复注入背景知识）。
- 收益判据见 SKILL.md 派发判据；核心是"任务独立数量"与"会话长度"——两者都不达标就不派。
- 用户明确要求省 token / 快速出结果 → 不派，写进声明。
