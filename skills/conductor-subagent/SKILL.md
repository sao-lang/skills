# conductor-subagent · 子代理派发器官

> conductor 机体的"外包车间"：主上下文只当调度台，重活派给干净上下文的子代理。
> **条件触发，AI 看着选**：派发省上下文但费 token，不达标不派；派与不派都必须写进路由声明。

## 输入

- 已确认的实施计划（含精确路径、验证步骤的任务列表）
- 当前上下文状态：已完成的任务数、会话长度、任务间耦合度

## 输出

- 每个被派发任务的：任务 brief + 子代理执行结果 + 两段评审结论（规格符合度 / 代码质量）
- 主上下文里只留：每个任务一行结论（通过/返修原因），不留子代理过程

## 派发判据（先判，再动手）

**派**（任一命中且无跳过条件冲突）：
- 计划含 **≥3 个相互独立**的任务（各自有精确路径与验证步骤）
- 多文件改动且任务间只通过计划里的 Interfaces 块衔接（无隐含上下文依赖）
- 会话已长（前面任务多），继续主上下文直做会污染后面对话质量

**不派**（任一命中即主上下文直做）：
- 任务数 ≤2 或单文件小修（派发开销 > 收益）
- 任务紧耦合：下一个任务必须看到上一个任务的完整实现细节才能写
- 调试类任务：根因探索需要跨任务上下文联想，子代理干净上下文反而丢线索
- 用户明确说"快点 / 别派子代理 / 直接写"

判据冲突时从严（多派），但**每次派与不派都写进声明**：`子代理：派（计划 5 任务独立）/ 不派（紧耦合）`。

## 执行

1. 按计划顺序逐任务派发；每个任务派**全新上下文**子代理，禁止复用旧子代理或旧报告。
2. **任务 brief 必须自包含**：计划里该任务的 Files / Interfaces / Steps 原文 + 验证命令。
   子代理只看 brief 和计划片段，看不到主对话——brief 里没有的等于不存在。
3. 子代理完成后走两段评审：先查规格符合度，再查代码质量；Critical/Blocker → 返修后**重派新子代理**复审。
   评审维度与分级的完整规则归 conductor-review，由 conductor 编排加载，本器官不重复定义。
4. 主上下文只记录一行结论；完整过程留在子代理，不回灌。

## 方法源

- `references/dispatch.md`（brief 模板、注入最小集、防污染纪律）

## 降级

- 无子代理能力（宿主不支持）→ 主上下文直做，写明「缺子代理 / 影响=上下文占用高 / 降级=直做+更频繁 self-check」。
- 子代理产出不可信（连续返修 ≥2 轮）→ 停下问用户，不要无限派发烧 token。

## 本器官自带（可独立工作）

- `SKILL.md`：派发判据、I/O、执行与降级
- `references/dispatch.md`：brief 模板与防污染纪律
- `scripts/`：无（派发是编排行为，由宿主执行）
